# 实现设计记录（scheduler 数据接口、功率模型与基线 MILP）

> 本文记录“代码实现层”的设计与口径，研究问题/创新点见 README。随实现推进持续更新。

## 1. 数据接口与单位口径

### 1.1 统一小时索引

- 能源窗口：4 个 ERCOT 2025 窗口，每个 30 天核心期 720 小时（另有 171h 上下文、171h 结算尾，调度只用核心期）。
- 算力侧：由 8 天 `batch_task` 用蒙特卡洛生成器扩展为 30 天 720 小时柔性包络（见 §2）。
- 两个 720 小时序列按小时对齐，`timestamp_utc` 以能源窗口 `interval_end_utc` 为准。

### 1.2 批处理需求：用 `baseline_energy_core_hours`，不用 `baseline_cores`

- `baseline_cores` = 该小时所有重叠任务的 `plan_cpu/100 × instance_num` 之和（把每个任务按整小时满功率计入），短任务会被高估，甚至超过集群核数，不能当功率用。
- `baseline_energy_core_hours` = 各任务 `(plan_cpu/100) × instance_num × 重叠小时` 的精确值，单位是 core-hours，等价于“该小时平均核数”，是可用口径。
- 因此调度器的可延迟需求统一取 `baseline_energy_core_hours`。

### 1.3 在线负载（必须满足）

- 用 `container_meta` 的 `cpu_request` 静态预留：`online_reserved_cores = 362,072` 核，当作恒定在线负载下界（无 usage 表，只能按静态预留近似）。

## 2. 工作负载扩展（方法 2）

- `scripts/generate_workload.py`：读 `compute_uncertainty.json` 的逐小时到达率，用 numpy `Poisson` 生成每小时到达数；每个到达有放回抽取真实任务记录（时长 + 能量），保留时长-能量联合分布。
- 输出 `data/workload/generated_envelope_30d.csv`（720 小时），消除 8 天滚动周期。
- 校验：30 天基线能量 = 8 天的 3.69×；窗口能量/基线能量 = 3.60×，与原 trace 一致。

## 3. 功率模型（cores → MW）

> 无 usage 表，故这是“资源需求代理”，不是实测功率；绝对量级是场景参数，结果重点在相对降本降碳。

```text
N_MACHINES = 4034（来自 machine_meta）
功率场景（无遥测，按 2018 年代约 96 核服务器公开区间设定）：
  low : PUE 1.10, idle 100 W/machine, active 2.0 W/core
  base: PUE 1.20, idle 150 W/machine, active 3.0 W/core
  high: PUE 1.40, idle 200 W/machine, active 4.0 W/core
```

```text
power_per_core_mw = PUE × active_w_per_core / 1e6
online_mw         = online_reserved_cores × power_per_core_mw        # 固定、必须满足
batch_mwh(t)      = baseline_energy_core_hours(t) × power_per_core_mw # 可延迟
base_mw           = PUE × N_MACHINES × idle_w_per_machine / 1e6        # 固定基座
```

诚实边界：`online_mw` 是静态预留（上界），`batch_mwh` 是 `plan_cpu` 计划需求；二者都不声称实测功率。基座功率在基线里为固定常数，不影响优化，仅用于功率平衡与总量报告。

## 3.5 不确定集标定：为什么用 2024 残差

- **残差是什么**：`残差 = 实际值 − 预测值`（同一套 48h 保护 Ridge 预测器产生的误差）。它刻画“预测有多不靠谱”，是能源侧不确定集的唯一证据来源。
- **为什么只用 2024**：
  1. **无泄漏**：标定集必须严格早于 2025、且不碰四个 2025 主窗口；用 2024 标定、拿到 2025 做样本外。
  2. **新鲜度/非平稳**：风光预测误差会随装机、预测技术、电网结构变化；2024 最接近 2025，比把 2015 一起拉进来更代表当前误差体制。
- **一年够不够**：
  - 对“边际分布”（均值/标准差/分位数/支撑集），一年 8760 小时绰绰有余：均值标准误 ≈ σ/√8760 ≈ σ/94。
  - 只有需要“条件结构”（按小时/月分组的异方差、残差自相关、逐年趋势）或升级 Wasserstein DRO 时，才需要多年；且多年要按新近加权，避免老体制污染。
- **当前做法**：能源侧 PV 相对误差 ε 取已提交 `inputs_manifest.json` 中 2024 Ridge 验证的太阳能 `ridge_nmae ≈ 0.243`（平均绝对相对误差）。更严格的“95 分位数相对误差”需要落盘 2024 全年带符号残差，作为后续增强项。

## 4. 基线 MILP（先确定性，后加 DRO）

> 完整数学公式与各类映射见 [model.md](model.md)。

### 4.1 变量（小时 t，0..719）

- `p_grid[t]`：购电功率（MW），≥0。
- `p_bess_ch[t]`, `p_bess_dis[t]`：BESS 充/放电（MW），≥0。
- `e_bess[t]`：BESS 能量（MWh）。
- `batch[t]`：调度后的可延迟功率（MW），在柔性包络内。

### 4.2 约束

1. 功率平衡：`p_grid[t] + p_bess_dis[t] + p_pv[t] = online_mw + batch[t] + p_bess_ch[t]`。
2. 批处理能量守恒：`Σ batch[t] = Σ batch_mwh[t]`（总可延迟能量不减少，只平移）。
3. 批处理柔性包络：`0 ≤ batch[t] ≤ window_mwh[t]`，其中 `window_mwh` 来自柔性窗口能量。
4. BESS SOC：`e_bess[t+1] = e_bess[t] + η_ch·p_bess_ch[t] − p_bess_dis[t]/η_dis`，`SOC_min ≤ e ≤ SOC_max`。
5. 并网/爬坡：`0 ≤ p_grid[t] ≤ G_max`，`|p_grid[t]−p_grid[t−1]| ≤ R_max`（扫参）。

### 4.3 目标层级（定稿：成本 → 碳）

采用**词典序**，两层：

1. 第一层：`min Σ dam_price[t] × p_grid[t]`（最小化总购电成本），得最优成本 `C*`。
2. 第二层：加约束 `Σ price[t]·p_grid[t] ≤ C*·(1+1%)`（成本保护带），再把目标改为 `min Σ 碳强度[t] × p_grid[t]`（最小化碳）。

**术语澄清**：这里的“词典序”是“两次顺序求解的单目标 LP”，**不等于**“两阶段 LP”。后者专指两阶段随机/鲁棒规划（第一阶段日前决策 + 第二阶段按实现再调度，是针对不确定性的结构），别混用。

**为什么不再设“风光匹配”这一层**：能源侧是 ERCO **系统级**风光/碳，2025 全年 `corr(系统风光, 碳强度) = −0.88`，风光匹配与碳最小化高度重复。因此风光匹配**降级为报告指标**（PV 自用率 / 弃电率），不作为独立目标。

**尖峰（G_max）、爬坡（R_max）是约束**，不是目标，通过扫参报告可行性边界（见 results.md §4.2–4.3）。**削峰不设为目标**，成本与尖峰的正常 tradeoff 由 G_max 扫参体现。

**为什么用词典序而非加权 `cost + λ·carbon`**：λ 无物理意义、还需扫 λ 说明取点；词典序只需两次 LP，可解释、无权重参数。

### 4.4 基线对照

- “无能源感知 + 不延迟”：`batch[t] = batch_mwh[t]`（观测值），BESS 不动作。

## 7. 主实验配置（最终取值与理由）

扫描实验是**敏感性分析**，不是“选出最优”。主实验固定一组可解释的 base 参数，扫描围绕它展开：

| 参数 | 主实验取值 | 为什么这样取 |
| --- | --- | --- |
| 功率场景 | base（PUE 1.20、150W、3W/core） | 三档中间值，low/high 做敏感性 |
| 并网上限 `G_max` | `1.0 × P_peak` | 按峰值负荷设计并网是默认做法 |
| 爬坡 `R_max` | `0.1 × P_peak/h` | 10%/小时是中等并网合同的常见爬坡值 |
| BESS 功率/能量 | `0.5 × P_peak`、2h | 收益曲线在 0.5 后明显变平（边际递减）；2h 是储能标准时长 |
| PV 容量 | `1.0 × P_must` | 按“白天 PV 平均覆盖必保负荷”的常用经验 |
| 鲁棒预算 `Γ`、`Γ_pv` | 报告 0→1 全谱 | Γ 不是要“选”的参数，而是论文要量化的“保守性—可靠性折中” |

具体依据：

- `G_max` 最小可行值是 `0.6×P_peak`（再低无解）；主实验用 1.0 是不让并网容量成为瓶颈，0.6 作为“容量受限”敏感性。
- `R_max` 最小可行值是 `0.05×P_peak/h`；主实验用 0.1 是中等爬坡。
- BESS 从 0 到 0.5 每档收益明显（16.5%→19.4%），0.5 之后每档只加 0.3–0.5 个百分点，故取 0.5 作为“边际收益拐点”。
- PV 取 `1.0×P_must` 表示“白天 PV 平均能覆盖必保负荷”；更高渗透率需要 BESS 吸收爬坡（见 results.md §4.5）。
- Γ 不做单点选择：论文同时报 `Γ=0`（确定性）与 `Γ=1`（完全鲁棒）及整条曲线，再用样本外回测证明鲁棒的可靠性收益。

## 8. 关键讨论结论（近几轮定稿）

1. **方法创新定位**：压在不确定性上（双侧 Γ-RO + trace 标定柔性），**不是**多目标、**不是**削峰。双目标（cost–peak/carbon）是老技术，不能包装成方法创新。
2. **数据事实**：能源侧是 ERCO 系统级风光/碳；本地 PV 是反事实（系统太阳形状 × 场景容量）。2025 全年 `corr(系统风光, 碳强度) = −0.88`。
3. **目标层级**：`min 成本 → 1% 成本带内 min 碳`（两层词典序）；风光匹配降级为报告指标（PV 自用率/弃电率）；尖峰是约束（G_max 扫参）。
4. **术语**：词典序（两次顺序求解）≠ 两阶段 LP（日前决策 + 再调度的随机规划结构）。
5. **求解方法**：词典序两次 LP，不用加权 `cost + λ·carbon`。
6. **论文支撑力判断**：能撑一篇，但当前“Γ-budget RO”偏保守缩放，需诚实命名或升级；且缺对照基线。下一步分两阶段：先实现“成本→碳 + PV 自用指标 + 重跑四窗口”，再做“鲁棒升级 + 基线”。
